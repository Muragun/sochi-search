# Поиск по sochi.ru

Внутренняя поисковая система по документам и страницам сайта
администрации Сочи. Обходит сайт, разбирает HTML, PDF и офисные файлы,
распознаёт отсканированные документы и складывает всё в Elasticsearch.

Версия 2.5.0.

---

## Развернуть на новой машине

```bash
git clone <адрес репозитория> /opt/sochi-search
cd /opt/sochi-search
bash deploy.sh          # создаст .env и остановится
nano .env               # заполнить три значения
bash deploy.sh          # соберёт и запустит
```

Подробно, со всеми оговорками — **[docs/DEPLOY.md](docs/DEPLOY.md)**.
Там же перенос данных со старой машины, ограничение доступа внутренней
сетью и что делать, когда что-то не заработало.

## Как этим пользоваться

| Адрес | Что там | Пароль |
| --- | --- | --- |
| `/ui` | поиск | не нужен |
| `/admin` | состояние, очереди, запуск задач | логин и пароль |
| `/search` | тот же поиск в виде JSON | не нужен |
| `/docs` | описание API | не нужен |

Раздел управления показывает, сколько документов в индексе, что делает
каждая очередь и на каком месте распознавание, и позволяет запускать
задачи кнопками, не заходя на сервер.

---

## Из чего состоит

```
app_v2/          поиск: API, разбор запроса, раздел управления
crawler_v2/      обход сайта, разбор документов, распознавание сканов
elasticsearch/   схема индекса
ops/             перенос индекса, резервные копии, проверки
docker/          точка входа образа
systemd/         юниты для установки без Docker
tests/           тесты
docs/            документация
```

Контейнеры повторяют роли: `api` отвечает на запросы, `worker` разбирает
очередь, `discovery` ищет новые адреса, `ocr-1` и `ocr-2` распознают
сканы, `publication-date` и `content-cleanup` доводят метаданные,
`backup` делает копии.

## Проверка кода

```bash
docker compose -f docker-compose.yml -f docker-compose.app.yml run --rm api tests
```

Или без контейнера, если рядом есть Python 3.8+:

```bash
python -m unittest discover -s tests -p "test_*.py"
```

185 тестов, из них 6 пропускаются: пять описывают снятый движок
распознавания (замена — `tests/test_v250_units.py`), один набор требует
установленного PyMuPDF. Пропуски объявлены явно и видны в выводе.

## Что изменилось в 2.5.0

Распознавание сканов ускорилось в одиннадцать раз и перестало выдавать
мусор: страница обрабатывается за 9,5 секунды вместо 157, и результат
читаемый, а не набор случайных символов. Причина была не в мощности
сервера — Tesseract подбирал порог яркости по всему листу сразу и на
выцветших ксерокопиях получал либо чёрное пятно, либо белый лист.

Индекс перестроен: свои анализаторы для русского языка, отдельное поле
для номеров документов, рубрики вычисляются при индексации, а не
перебором адресов при каждом запросе.

Добавились форматы `.rtf`, `.odt` и `.ods` — около 1700 документов,
которые раньше просто пропускались.

Появился раздел управления в браузере: раньше всё делалось командами на
сервере.

Подробности и измерения — [docs/CHANGES_RC4.md](docs/CHANGES_RC4.md).
