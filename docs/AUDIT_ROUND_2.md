# Второй проход аудита: поиск, API, интерфейс, остальные воркеры

Проверялось то, что не входило в первый отчёт: постобработка выдачи,
эндпоинты, интерфейс, чанкование, резервное копирование, сетевой слой.

---

## 1. Дефект в самом патче 2.5.0

Нашёлся при проверке связок и был бы обнаружен только на сервере.

**`app_v2/search_query.py` нигде не подключался.** Модуль с новым
построителем запроса был написан, покрыт тестами и импортировался только
самими тестами и валидатором. `search_service.py` продолжал использовать
свой прежний `build_search_body`. То есть весь разбор запроса, отказ от
мёртвых полей и новые агрегации в рабочем API не действовали бы вообще.

Исправлено: старый построитель (491 строка) удалён, сервис импортирует
новый модуль.

**Формат агрегации фасетов был несовместим.** Прежняя `filters`-агрегация
отдаёт словарь именованных корзин, новая `terms` — список корзин с ключом
в поле `key`. `search_documents` читал их как словарь, поэтому счётчики
всех вкладок стали бы нулями. Исправлено, разбор принимает обе формы.

**Рубрика применялась как обычный фильтр вместо `post_filter`.** Это
сузило бы и агрегации: счётчики невыбранных вкладок обнулились бы.
Исправлено.

Добавлен класс тестов `SearchWiringTests` — он подставляет поддельный
Elasticsearch и проверяет, что сервис действительно шлёт новый запрос, а
фасеты разбираются. Модуль можно написать правильно и забыть подключить;
тесты самого модуля этого не замечают.

## 2. Поиск падал без PyMuPDF

`search_service.py` импортирует `crawler_v2.pdf_ocr` ради одной функции
`looks_like_garbled_text`, а тот на верхнем уровне делал `import pymupdf`.
Любой сбой PDF-библиотеки — несовпадение версии, повреждённый пакет после
обновления — ронял API поиска на старте, хотя поиску PDF-библиотека не
нужна.

Импорт `pymupdf` перенесён внутрь `run_ocr_self_test`, единственной
функции, которой он нужен. Добавлен тест, запускающий импорт сервиса при
намеренно сломанном `pymupdf`.

## 3. Качество выдачи

**Дата документа выводилась в ISO.** Для акта без собственного заголовка
титул собирается из реквизитов и выглядел как «Постановление № 512-р от
2024-03-14». Сотрудник ищет «постановление от 14 марта 2024». Добавлена
`format_document_date`, титул стал «Постановление № 512-р от 14 марта
2024».

**Оценка качества текста считалась дважды на каждый результат.**
`looks_like_garbled_text` перебирает все символы фрагмента, считает доли
письменностей, гласных, регистров и подозрительных знаков. Она вызывалась
и в `get_title`, и затем в `normalize_hit` — двадцать проходов по
фрагментам на страницу выдачи из десяти результатов. Теперь считается
один раз и передаётся дальше.

**Глубокая пагинация упиралась в ошибку.** `offset` допускался до 10000
при `limit` до 50, а `from + size` не может превышать
`index.max_result_window` (10000). Последняя страница выдачи отвечала
ошибкой Elasticsearch. Предел `offset` снижен до 9000, плюс `limit`
подрезается, если сумма всё же выходит за окно.

## 4. Сетевой слой

`app_v2/es_http.py` не имел ни повторов, ни настроенного пула соединений:
одиночный сетевой сбой или короткая недоступность узла превращались в
ошибку пользователю. Добавлен `HTTPAdapter` с двумя повторами на кодах
502/503/504 и пулом на 16 соединений.

## 5. Память Elasticsearch на общем сервере

У контейнера не было предела памяти при `-Xmx2g`. Elasticsearch занимает
heap плюс сопоставимый объём вне heap, а на этой машине рядом работают
PHP-FPM, MariaDB и Node — при 96 % занятой памяти соседи уходят в swap.
В `docker-compose.yml` добавлены `mem_limit: 3g`, `memswap_limit: 3g` и
`ulimits` для memlock и nofile.

## Что проверено и оказалось исправным

Чтобы список правок не создавал ложного впечатления:

- **Разбиение на фрагменты** — границы ищутся по концам предложений,
  перекрытие соблюдается, прогресс цикла гарантирован (`start + 1`),
  зацикливания нет.
- **Резервное копирование** — используется штатный `sqlite3.backup()`,
  то есть согласованный online-снимок, с последующей проверкой
  `PRAGMA quick_check`. Корректно.
- **SQL** — параметризованные запросы везде, ни одной строковой склейки.
- **Внешние команды** — ни `shell=True`, ни `os.system`, ни `eval`.
- **Сетевые вызовы** — таймаут задан у всех до единого (проверено
  разбором синтаксического дерева, не поиском по тексту).
- **Интерфейс** — DOM собирается через `createElement`, `innerHTML` не
  используется нигде, подсветка совпадений безопасна.
- **Проглоченные исключения** — восемь мест, все в путях завершения
  процессов, где это оправдано.
- **Совместимость с Python 3.8** — во всех модулях `from __future__
  import annotations`, конструкций 3.9+ нет.

## Не исправлено: требует решения владельца

**Python 3.8.10 снят с поддержки** в октябре 2024 года: обновления
безопасности для него не выходят. Ubuntu 20.04 другой версии не даёт.
Переход на 22.04 или 24.04 решил бы это и заодно принёс Tesseract 5.

**Tesseract 4.1.1.** На стенде та же по классу страница обрабатывалась
заметно быстрее на 5.3.4. Обновление на 20.04 требует стороннего PPA —
на общем сервере это отдельное решение, а не техническая правка.

**Определение PDF при скачивании.** В журнале worker отказал файлу с
расширением `.pdf` по лимиту для не-PDF (50 МБ вместо предусмотренных для
PDF). Разбор `response_is_pdf` показывает, что при коде 200 и
`content-type: application/pdf` ветка сработать не должна. Нужен
прицельный прогон на сервере, чтобы не чинить вслепую.

**Legacy-контур.** Индекс `sochi_docs` на 98547 документов и API v1
продолжают работать. Если они не нужны, их отключение освободит память,
которой на этой машине мало.

**Порог размера PDF.** В очереди есть файл на 262 МБ; 70-мегабайтный
занимал worker 18 минут. Предлагается порог 150 МБ со статусом
`skipped_too_large`: документ остаётся находимым по заголовку и
реквизитам, но не блокирует конвейер. Значение требует согласования.

**Общая сессия `requests` в API.** `requests.Session` формально не
потокобезопасна, а FastAPI выполняет синхронные обработчики в пуле
потоков. Пул соединений urllib3 под ней потокобезопасен, и при внутренней
нагрузке риск незначителен, но при росте числа пользователей сессию стоит
делать по потоку.
