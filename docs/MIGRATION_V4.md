# Переход на схему v4 и распознавание v7

Что меняется, в каком порядке это применять и как откатить.

Два независимых изменения. Их можно делать по очереди и между ними
остановиться:

- **схема индекса v4** — новое поле номера акта, исправленный анализатор,
  кавычки и минус-слова в запросе;
- **распознавание v7** — только русский язык, повторы по уверенности,
  склейка переносов.

Первое не требует повторного обхода сайта: текст уже лежит в
Elasticsearch, переносится он внутри кластера. Второе перечитывает
сканы заново и идёт фоном.

---

## Коротко

```bash
# 1. Проверить схему на кластере, ничего не меняя
python -m ops.validate_elasticsearch --mapping elasticsearch/sochi_docs_v4.json

# 2. Создать новый индекс и перенести документы
python -m ops.reindex --create --reindex --verify

# 3. Переключить alias
python -m ops.reindex --switch

# 4. Запустить перечитывание сканов
systemctl restart sochi-search-pdf-ocr@1 sochi-search-pdf-ocr@2
```

Откат alias — одна команда:

```bash
python -m ops.reindex --rollback --previous <прежний индекс>
```

---

## Шаг 1. Проверка схемы

```bash
python -m ops.validate_elasticsearch --mapping elasticsearch/sochi_docs_v4.json
```

Создаёт временный индекс, прогоняет анализаторы и запросы, удаляет за
собой. Рабочий индекс и alias не затрагиваются.

Проверок стало больше, и три из них — про то, что менялось:

- **«№ 84 – PC» нормализуется в «84-рс»** — цепочка `char_filter` в схеме
  приводит номер к тому же виду, что и функция запроса;
- **индексный анализатор номера не оставляет граф** — `positionLength`
  всех токенов равен единице;
- **точная фраза в кавычках находит документ, переставленная — нет.**

Если первая из них не проходит, дальше идти нельзя: точное совпадение по
номеру снова окажется случайным.

Отдельно стоит убедиться, что кластер принимает `mapping`-фильтр из
57 правил — он длинный, но обычный. Ошибка при создании индекса будет
видна сразу, на шаге создания, а не потом.

## Шаг 2. Перенос документов

```bash
python -m ops.reindex --create --reindex --verify
```

Создаёт `sochi_docs_v4_ГГГГММДД`, переносит документы через `_reindex`
внутри кластера и сверяет число документов и контрольные запросы.

Номера актов старых документов канонизируются **сами**: `_reindex`
записывает документ в новый индекс, а новый индекс применяет свой
нормализатор. Отдельный скрипт для этого не нужен, и второй реализации
нормализации, которая могла бы разойтись с первой, не появляется.

Поле `document_number_normalized` у перенесённых документов остаётся
пустым — его заполняет обходчик при следующей обработке адреса. До тех
пор точное совпадение обеспечивает нормализованный `document_number`:
в запросе он идёт второй клаузой с весом 0,8 от основной.

Прежний индекс не удаляется.

## Шаг 3. Переключение alias

```bash
python -m ops.reindex --switch
```

Одна атомарная операция, промежуточного состояния поиск не видит.

После этого стоит пройти десяток типичных запросов сотрудников и
сравнить выдачу с прежней. Обязательно — запрос по номеру акта в
нескольких написаниях: `512-р`, `№ 512-р`, `512 Р`.

## Шаг 4. Перечитывание сканов

`PDF_EXTRACTION_VERSION` поднят с `pdf-ocr-v6` до `pdf-ocr-v7`, поэтому
фоновый проход считает все PDF нуждающимися в перечитывании. Это
намеренно: результат распознавания изменился, и на части документов
существенно.

```bash
systemctl restart sochi-search-pdf-ocr@1 sochi-search-pdf-ocr@2
journalctl -u 'sochi-search-pdf-ocr@*' -f
```

Поиск при этом продолжает работать: страницы заменяются по мере
готовности, документ не исчезает из индекса на время перечитывания.

Сколько это займёт — зависит от доли страниц, уходящих в лестницу
повторов. Страница с нормальной уверенностью распознаётся ровно как
раньше; страница с низкой — до пяти попыток вместо одной. Верхняя
граница на страницу задаётся `CRAWL_PDF_OCR_LADDER_BUDGET_SECONDS`
(по умолчанию 150 секунд).

Если перечитывать весь корпус сейчас не нужно, оставьте `pdf-ocr-v6`
в `crawler_v2/pdf_ocr.py`: новые документы пойдут по новому пути, старые
останутся как есть.

## Что изменилось в настройках

Новые ключи, все со значениями по умолчанию — трогать не обязательно:

| Ключ | По умолчанию | Зачем |
| --- | --- | --- |
| `CRAWL_PDF_OCR_CONFIDENCE_FLOOR` | 65 | ниже — страница пробуется ещё раз; 0 отключает повторы |
| `CRAWL_PDF_OCR_RETRY_ROTATIONS` | 90,270,180 | какие повороты перебирать |
| `CRAWL_PDF_OCR_SAUVOLA_K` | 0.15 | основной порог бинаризации |
| `CRAWL_PDF_OCR_RETRY_SAUVOLA_K` | 0.10 | мягкий порог для второй попытки |
| `CRAWL_PDF_OCR_LADDER_BUDGET_SECONDS` | 150 | потолок времени на страницу со всеми повторами |

Изменилось одно значение по умолчанию:

| Ключ | Было | Стало |
| --- | --- | --- |
| `CRAWL_PDF_OCR_LANGUAGES` | `rus+eng` | `rus` |

В `.env.production.example` уже стояло `rus`, поэтому на сервере, где
`.env` собран из этого файла, ничего не изменится. Значение по умолчанию
расходилось с рекомендованным — это чинится здесь.

## Откат

| Что откатывать | Как |
| --- | --- |
| Схема индекса | `python -m ops.reindex --rollback --previous <индекс>` |
| Повторы OCR | `CRAWL_PDF_OCR_CONFIDENCE_FLOOR=0` |
| Язык распознавания | `CRAWL_PDF_OCR_LANGUAGES=rus+eng` |
| Движок распознавания целиком | `CRAWL_PDF_OCR_ENGINE=pymupdf` |

Откат схемы возвращает поиск на прежний индекс, который всё это время
лежал нетронутым. Запрос при этом продолжит спрашивать поле
`document_number_normalized`, которого в старом индексе нет: в
Elasticsearch `term` по отсутствующему полю просто не находит ничего и
ошибкой не является, остальные клаузы работают как раньше.

## Проверить после перехода

1. `_cat/indices?v` — размер нового индекса.
2. Запрос по номеру акта в трёх написаниях даёт один и тот же документ.
3. Запрос в кавычках сужает выдачу, а не повторяет её.
4. Минус-слово убирает документы, а не добавляет.
5. Распределение `ocr_confidence` в индексе: по нему видно, какие
   документы стоит перечитать во второй проход.

```bash
curl -s "$ES_URL/sochi_docs/_search" -H 'Content-Type: application/json' -d '{
  "size": 0,
  "aggs": {
    "confidence": {
      "range": {
        "field": "ocr_confidence",
        "ranges": [
          {"to": 50}, {"from": 50, "to": 65},
          {"from": 65, "to": 85}, {"from": 85}
        ]
      }
    }
  }
}'
```
